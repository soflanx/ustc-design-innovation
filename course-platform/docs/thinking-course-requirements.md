# 设计创新思维课程需求分析

需求基线：v1。更新日期：2026-11-08。

## 文档目的与范围

本文从真实教学工作出发，说明师生要完成什么、彼此如何交接，以及网站应提供什么支持，作为后续设计与实施的依据。范围仅为设计创新思维课；实践课另行分析。本文不规定最终页面布局，也不代表所述能力已经实现。

依据分为三类：**用户确认**决定业务规则；**课程计划与样本事实**帮助理解实际工作；**分析推导**提出实现这些要求的组织方式。旧聊天中的 Chat 建议不等于用户确认。发生冲突时，以本轮用户最新说明为准。下文“已确认规则”可直接作为设计约束，其余组织与实施建议仍可在设计中调整。

## 一 真实教学工作与期望结果

### 学生要完成的学习

学生通过观察、调研、讨论、原型与测试，逐步理解问题、形成方案，并说明自己的判断依据。每组通常围绕自己的一个主项目，形成学期主要成果。中间的调研、原型和方案汇报可以服务于它；Paper Robots、参观及其他练习也可以独立存在，不必都解释成主项目的阶段。

学习既有按周进行的课程，也有横跨数周的工作。学生需要知道这次课学了什么、接下来做什么、哪些旧任务仍在进行；与组员共同工作时，需要留住有用的材料和决定；到正式交付节点，需要清楚地交回成果并得到回执。收到指导后，项目继续发展，不以反复重交同一作业作为默认学习过程。

成功不只是“文件上传成功”，还包括学生能找到要求和材料，理解反馈针对什么，把它用于后续工作，并在学期末说明成果如何形成。过程记录是自愿的辅助，不构成额外的强制学习日志。

### 教师与助教要完成的工作

教学团队安排课堂活动、提供资料、明确交付要求，现场了解学生的思考与合作，给出指导，并持续保存对学生或小组的观察。既要能按同一任务看全班，也要能接着跟进一个小组，或回顾某位学生整学期的经历。

在多教室分组汇报这类教学场景中，教学团队需要迅速找到课题、成果和成员。个人点评不一定发生在评阅文件时，也可能来自课堂交流、项目讨论或合作情况。记录不应以先创建作业、给分或填写完整表格为前提。

期末需要将已有材料和观察放回情境中理解，而不是重新在各次文件和聊天中搜集。教学团队应能方便地记录和回看文字观察，期末再按需追加一条总结。

### 对外说明成果

学生希望展示的是本组主要成果及其价值，并选取必要的过程说明设计选择。班内同学和互联网读者需要读懂问题、方案与成果，不需要进入完整内部工作空间。展示应经过教学团队确认，不能把内部观察、中间材料和全部作业自动公开。

## 二 一个学期中的关键场景与交接

### 开始课程并组织合作

学生可以通过个人介绍表达学习动机、兴趣与合作经历。这类材料是学生自述，应作为学习起点保留，与教学团队后来形成的观察区分。个人课务、资料阅读和个人提交不以先有小组为条件。

第一次上课前，学生打开本期课程就能看到组队是否开放和怎样参与。还没约好搭档的学生可发起招募或加入本班有余位的组，已约好的同学可用邀请链接确认加入。教师说明课上的合作安排，并为本期开设组队时间和人数规则。需要帮助的同学可以联系教学团队。学生确认后即进入正式小组，个人课务可在入组前开展。正式组形成后尽量稳定，遇到合作困难等情况时由教学团队协助调整，已有成果仍归属于提交时的参与者。

交接完成的条件是：学生知道自己当前与谁合作，团队能找到该组及成员；既往个人材料和已有成果仍能找到，不因分组或调组而消失。

### 课前安排与课后回看

教师或助教整理课次页面，说明本次学习内容、活动、材料和后续工作。页面可以课前先发必要安排，课后补课堂展示与回顾，保持类似 wiki 的连续阅读方式。

周次、上课日期与作业截止是不同信息。课程计划中 Paper Robots 跨假期推进，在不上课的那周交视频，说明跨周任务必须持续可见。计划中写“报告”或“测试”，不自动等于要求在线提交；是否收材料以及截止时间，应由实际布置确定，不能从课程日期反推。

学生读完说明应能直接取得相关资料、进入对应作业或小组工作；下周页面更新后，仍能找到未结束的任务和旧课次。老师不应每周重新上传相同资料、复制相同要求。

### 现场汇报与持续指导

以需求与竞品调研汇报为例，团队需要在课前说明现场安排；确实需要交材料时，关联正式作业。现场助教从小组进入，看到课题、成员与对应成果，能给小组指导，也能对某名学生留下内部观察。无需上传的课堂活动同样可以被点评。

一次评阅可能需要同时查看多份材料，并在正文、图表及相关成果之间核对。网站不应预设一个文件就等于全部作业内容。

交接完成的条件是：团队能指出指导所针对的成果或情境；需要学生看到的反馈能到达对应学生或小组，内部观察则仅由教学团队读取。学生随后继续项目，而不是为了接收点评被迫再交一版。

### 正式交付与更正

学生按个人或小组完成一次正式交付，可以包含文字、PDF、视频等多份材料。小组成员代表本组提交，其他成员能看到同一份成果和回执，不各交一份。提交单位与是否服务主项目分别表达：个人任务可能服务本组项目，小组练习也可能独立于主项目。

截止前学生可以更正，截止后由教学团队明确开放。这里的开放针对已交成果的更正，不包含首次补交或全班延期的授权。界面始终突出一份当前正式成果，同时保留更正前材料与痕迹。更正不是要求学生开展多轮提交和复评；已有历史版本与反馈不能被覆盖或删除。团队应能辨认某条反馈针对的是更正前还是当前材料，不能默默把旧评语移到新内容上。

交接完成的条件是：学生回执与团队收到的当前材料一致，提交要求、当时组员和更正历史可查。截止后未获开放的尝试不改变正式成果。开放更正的适用对象与条件必须清楚，不能为了处理一份材料而无意改变全班的截止。

### 期末回顾与成果展示

团队按学生回看其个人材料、当时参与的小组成果及历次观察，必要时追加期末文字总结。小组成果提供经历背景，不自动证明某人的具体贡献；学生自述、直接观察和同伴转述应保留来源区别。

小组围绕主要成果整理展示内容，复用已有作品和选定过程材料。教学团队确认后，按指定范围供全班或互联网阅读。班内确认不等于互联网确认，内部点评不作为展示内容或公开审核对象。成果的日常修改不应未经确认就进入已发布展示。

## 三 已确认的业务规则

| 事项 | 规则与边界 |
| --- | --- |
| 课程组织 | 思维课按周开展，课次可以补充回顾，跨周工作保持连续；资料与作业独立保存并引用。 |
| 小组 | 学生在本期开放范围内自行确认加入正式小组。教学团队负责规则和必要的调整，组籍历史保留。 |
| 过程记录 | 鼓励、自愿，不以缺少记录推定缺勤、未参与或贡献不足。 |
| 正式交付 | 个人或小组的一份当前正式成果可含多种材料；截止前可更正，截止后须团队开放，更正留痕。 |
| 点评 | 支持学生本人、该学生的某次作业、小组三种对象；内部记录默认仅本期教学团队可见，只有明确使用“给学生／小组反馈”动作才外发。 |
| 内部评价 | 方便输入文字，作者与记录时间自动保存；不做分数、权重或独立总评表，不向学生发布成绩。 |
| 教学协作 | 教师和助教共享资料、作业、点评、调组等主要教学工作，保留实际作者，按教学动作授予权限。开课、归档和授予权限仍按各自管理规则授权，不随助教教学权限一并扩大。 |
| 展示 | 全班和互联网两种范围都需教学团队确认，不随内部工作空间一起开放。 |

## 四 从任务推导网站支持

### 课程入口与独立记录

建议课程首页同时呈现近期教学说明、仍在进行的任务和可回看的课次，不做只有数字的管理面板。课次正文引用独立作业、资料及小组入口；同一作业可出现在多周页面，要求与交付状态保持一致。老师在编写正文时即可创建或引用相关记录，减少往返后台。

ME310 参考图的价值是将说明、日期、材料和行动入口放在同一上下文，并保留稳定栏目入口。它不决定本站样式，也不能作为审批或权限规则的证据。

### 小组工作与阶段成果

“我的小组”可以直接打开以本组主项目为中心的空间，先说明现在研究的问题和方案，再承接过程、成果与面向组员的指导。不要求学生在多个管理模块中逐层寻找。

例如，全班共用一项阶段作业时，各组交回各自项目的成果；不能把作业定义绑死在某一个小组项目上。服务主项目的正式交付与本组项目关联，独立练习仍可单独存在。首轮即应让学生实际保存简短文字、照片或材料，按需补充发生时间和参与者，之后能在组内重新找到，供组员和教学团队理解过程。记录保持自愿，区分记录者与填写的参与者，参与者列表本身不证明具体贡献；不将技术保存历史冒充真实活动时间轴。更完整的时间轴和检索可以后续完善。

### 任务、小组和学生之间互通

团队按任务看全班交付，按组看连续工作，再从成员进入某位学生。按学生查看时，教学团队可以汇集其个人材料、组籍变化、当时参与的正式成果、明确关联的活动和内部点评，不要求学生重复维护个人档案。

这里应区分阅读权限、历史参与关系与具体贡献。调组后，学生仍能读取自己原来参与的正式成果及原有面向其的反馈，原组后续内部工作不自动向其开放。为接续共同工作，新成员可以阅读新组已共享的既有项目材料、成果及面向全组的指导，但不会被追溯加入这些成果的历史参与者，也不能由阅读或当前组籍推定其贡献。个人专属反馈和教学团队内部观察不会随小组材料向其他学生扩散。

## 五 点评与材料流转的边界

### 对象、上下文与可见范围分别表达

点评对象回答“在谈谁”，上下文回答“针对什么事情”，可见范围回答“谁能读”。挂在作业或小组上，不代表自动发给学生或全班。

| 内部点评对象 | 可以关联的上下文 | 记录方式 |
| --- | --- | --- |
| 学生本人 | 课堂交流、合作情况、阶段回顾，也可不关联具体作业 | 选中学生后直接写，自动记作者和时间。 |
| 该学生的某次作业 | 个人提交，或其参与的某次小组成果 | 关联学生和对应成果，不复制个人提交。 |
| 小组 | 小组合作、项目方向、某次汇报或成果 | 从小组或任务入口记录，默认仍为内部点评。 |

共同作业中对某人的观察应同时连接该学生与该次组成果；组级提交维持原状，也不据此把整项成果计为该生贡献。针对作业记录时，自动保留当时所见材料的上下文，更正后仍能知道原点评针对什么，不要求用户选择技术版本。场景、实际发生时间或来源可按需补充，不强迫每次随手记录填写复杂表单。期末总结沿用同一种文字记录。

另提供明确的“给学生／小组反馈”动作，发送前让团队知道接收对象。内部记录不会因为选了作业而外发，也不要求每次打字都选择复杂权限。面向学生的指导与内部观察可以来自同一次现场活动，但分别保留用途和读者。面向全组、用于共同工作的指导可供新组员接续阅读；针对某个人的专属反馈不因此变成全组可见。

### 工作材料、正式成果与展示材料

工作材料可以持续修改；正式成果保留交付时的内容和更正痕迹；展示只使用选定并经确认的内容。应尽量复用已有材料，避免学生在项目、作业和展示中反复上传；复用不等于把后来的修改静默覆盖原交付或已确认展示。

外部链接可作为材料入口，但保存网址不等于固定外部作品内容。需要留存交付依据时，采取何种文件保存或导出方式在实现中细化，不宣称已冻结外部平台。往届成果可以经选择成为资料，不能把全部历史提交自动变成案例库。

## 六 用真实任务验收

以下是待实施后的验收要求，不是本轮已经完成的测试。

| 任务 | 应达到的结果与具体边界 |
| --- | --- |
| 教师整理和更新课次 | 在正文中组织说明、课堂展示和回顾，上传或引用资料、创建或引用作业；跨周复用同一记录，无需重复创建或上传。学生从发布后的正文直接取得材料或进入对应提交。 |
| 学生跟进跨周任务 | 从课次读要求并提交；换到下一周或不上课的周仍能找到任务。未布置在线交付的活动不凭空出现“未交”。 |
| 个人进入课程 | 尚未完成分组时也能读课次、交个人材料；自述保留原来源，不显示为教师评价。 |
| 首次组队 | 从课程首页可看见是否开放和下一步。未分组学生能从招募或邀请确认加入，回到首页能核对当前组。教学团队能看到真实组籍，其他同学只能看到本班招募所需的信息。 |
| 自愿保存过程记录 | 学生保存简短文字及照片或材料，可按需补时间和参与者；之后能重新找到，组员和教学团队可读，未记录不会产生未完成或缺勤判断。 |
| 一组交付并更正 | 组员读到同一当前成果与回执；截止前更正留痕，截止后未开放的尝试不改成果，开放后仅适用于指定已交成果，不让未交者借此首次补交。 |
| 现场记录个人点评 | 助教从组员进入，关联该次组成果并直接写内部观察；学生端及其数据读取均不可见。显式反馈后，仅正确接收对象可读。 |
| 调组后继续学习 | 学生仍可读原来参与的正式成果及面向其的反馈，不能因原组籍读原组后续内部工作；可读新组已共享的既有项目材料、成果和全组指导，但历史参与名单不变，个人专属反馈和内部观察不扩散。 |
| 期末按人回看 | 找到个人材料、相关组成果和历次文字观察，可追加总结；没有过程记录不会产生负面判断或自动扣分。 |
| 确认成果展示 | 内部点评和未选材料不出现；仅获班内确认的内容无法从互联网公开入口读取，互联网范围需单独确认。 |

## 七 实施建议与现有基础

先打通一轮真实教学：课次与跨周任务、正式材料交付及更正、现场内部点评、面向学生反馈、按任务／组／学生接续查看，以及助教必要操作权限。首轮同时提供能保存并重新找到文字和材料的轻量过程记录，之后再完善时间轴、检索与材料关联，随后接通成果选材、团队确认与分范围发布。每轮验证接手方实际收到什么，不以页面数量作为完成标准。

后续交互走查可以采用课程计划中 10 月 31 日的多教室分组点评作为样例，串起课次整理、学生准备与交付、现场记录、课后按学生回看。计划安排不代表当天实际执行细节已知。

以下现状来自初稿作者当时的代码核对，本次文本修订没有重新验证功能。按该核对结论，现有原型可复用课程成员与组籍历史、Markdown 子页、独立作业和资料引用、草稿发布、资料文件交付、提交回执、要求与参与者快照、版本反馈和访问控制。主要差距是：课次缺少明确教学周序；作业仍是文字及多版本主流程，未接通作业附件与截止后开放更正；小组自由正文尚非活动过程；现有评语直接面向提交版本，不能充当默认内部点评；缺少按学生串联观察及成果审核展示；助教调组等权限需按动作调整。

数据库中有模型不代表已有可用流程。改造应保留历史正式版本及反馈，不通过放宽整个课程管理权限来开放助教教学动作，也不把现有外发评语直接改名成内部记录。

本阶段不建设复杂项目管理、强制过程日志、贡献推断、评分引擎、问卷采集工具或文档级精细批注。学校认证与名单对接沿用既有范围，不在本文重新扩展。上传限额、媒体处理、预览方式、页面布局及操作细节留给实现设计；这些不构成再次索取材料或业务确认的前提。

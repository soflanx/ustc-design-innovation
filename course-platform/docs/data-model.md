# 数据模型

演示账号、人物、小组、新闻与项目均为虚构。seed 使用稳定 ID，只创建缺失记录；重跑不清空业务数据或覆盖教师编辑，不生成学生成绩。

Course 是长期课程，Term 是学期，CourseOffering 是课程在学期中的开课。CourseStaff 仅保存长期教师负责人，应用创建开课时将其带入 CourseMember。User 跨学期；isAdmin 独立于教学角色，教学角色不授予代码部署权限。isDemo 标识本地演示白名单。

CourseSubpage 直接归属一次 CourseOffering，没有 parentId，不会出现第二层子页。网址使用不可变 ID。公开标题及正文与教学团队草稿分开，revision 拒绝过期覆盖；撤回清除 publishedAt 并保留草稿，重新发布沿用原网址。学生的目录查询与详情查询均排除未发布页面。CourseFocus 与 CourseSubpage 使用相同的文档格式：连续 Markdown 以原文保存，结构化教学引用只保存记录 ID，服务端按当前角色投影可读取的引用。

CourseMember 每开课每用户唯一。Group 每开课名称唯一。GroupMember 与 TaGroupAssignment 保存历史，以 leftAt/endedAt 关闭记录。当前假设一个学生每次开课仅一个活跃组，partial unique index 落实。每组可有多名助教，同一组/助教仅一个活跃分配。小组成员须为 STUDENT，助教分配须为 TA。已有学业记录的成员不可直接改角色；已有提交的作业不可改模式。

自助组队窗口由 CourseOffering 保存，每次关闭后重开使用新的窗口 ID。Group 的招募方式、说明和邀请凭据与内部工作记录分开，窗口须与本期当前开放窗口相符才会接受入组。老小组的招募配置为空。学生确认建组和加入都直接写入 GroupMember，事务内检查账号、当前组籍、截止及有效人数。重复请求查同一条组籍记录，调组后返回当前归属。归档清除开放窗口，已有组籍和历史继续保留。

开课范围内的关系使用 (id, offeringId) 复合外键，防止组员、助教分配、作业提交、版本、提交者、参与者、评阅、成绩、历史、文件附件、小组页面以及观察与反馈的对象、成果上下文和收件人跨期引用。旧 TeachingNote 保留同开课作者 courseMemberId 以兼容既有数据。当前课堂记录使用 TeachingObservation，旧外发留言继续存于独立的 TeachingFeedback。

Assignment 区分个人/小组，Submission 的 courseMemberId/groupId 必须且只能填一项，且与作业模式相符。每作业每个人/小组仅一个提交容器，其最新封存版本是当前正式成果，更正前版本按需回看。SubmissionVersion 按容器版本号唯一；submittedById 记录实际提交者，finalizedAt 表示正式封存。封存前可在事务内组装参与者快照及附件；封存后版本禁止改删、参与者和附件禁止增改删。关联变更先锁版本行，避免与封存并发穿透。Review 必须指向封存版本，旧反馈不会移到更正后的材料。

GradeRecord 每作业每学生唯一，含 DRAFT/PUBLISHED、publishedAt、reviewId、updatedById。数据库验证发布状态与时间一致、成绩对象为 STUDENT、评阅者和改分者为 TEACHER/TA、评阅来源与作业和学生版本快照匹配。GradeHistory 保存 actorId、recordedAt、reason、previousScore、score 和 status，禁止改删。服务端必须在同一事务写当前成绩和历史；数据库未自动生成历史或核对前后分数。分数使用 Decimal(8,2)。这些字段和约束仅为兼容既有数据保留；当前教学流程不录入分数、不发布成绩，也不建设总评算法。

FileObject 保存 offeringId、ownerId、原文件名、大小及可选 bytes；当前上传把原始字节存入 bytes，保留旧 storageKey 字段。SubmissionFile 以复合外键关联同开课版本与文件。一次正式成果可包含说明及多份附件，至少有其中一项：说明最多 12000 字，附件最多 20 个、保留与新增文件合计不超过 10 MiB。更正可保留原附件、移除当前成果中的引用或加入新附件；所有文件、关联、参与者与版本在同一事务中写入并封存，移除引用不删除历史文件。已被封存版本引用的 FileObject 字节和元数据也禁止改删。

附件读取由服务端按开课、作业、封存版本及当前账号重新授权，不因知道文件 ID 就可下载。目录和成果查询只返回文件元数据；授权后的文件路由才读取字节。只有文件名为 PDF 且内容有 PDF 标识时允许新标签页内联阅读，其余文件（包括 HTML/SVG）强制下载，并设置私有不可缓存、nosniff 与沙箱响应策略。助教分组是职责分工，当前授权允许其阅读与反馈本期全部提交。

Submission 的 correctionUntil、correctionRevision 保存指定成果的更正期限和并发修订；SubmissionCorrectionEvent 追加记录操作者、修订、期限与记录时间，禁止事后改删。截止前沿用正常提交权限；截止后仅本期有效教师或助教可以为已有封存成果的指定 Submission 开放未来期限、调整或撤销。操作核对账号和修订，并在事务中写期限与事件；学生最终封存前再次核对期限。它不改变 Assignment.dueAt，不授权未交者首次补交，也不能重开已结束、已取消作业或已归档课程。

TeachingObservation 仅本期有效教师与助教可读。以学生或小组为对象时，`targetMemberId` 和 `targetGroupId` 中仅填一项。以整堂课为对象时，两项均为空，须有同期开课的 `pageId`，且 `versionId` 和 `contextGroupId` 均为空。学生或小组记录可通过 `versionId` 关联当时所见的封存成果。个人记录按个人归属或参与者快照核对关联，小组记录核对提交所属组。`authorUserId` 和 `createdAt` 分别保存作者及实际登记时间，`context` 保存情境或来源。`observedAt` 可选，新写入的值只表达北京时间的日历日期，最晚可填当天。

`kind` 可空，`TeachingRecordKind` 区分 `OBSERVATION`（现场观察）、`PARTICIPATION`（课堂发言）、`LEAVE_REPORTED`（收到请假）、`LEAVE_CONFIRMED`（已确认请假）和 `TEACHING_JUDGMENT`（教学判断）。两类请假记录以学生为对象，已确认请假要求填写来源。学生或小组记录可选 `pageId`，以复合外键关联同期开课的 CourseSubpage。`contextGroupId` 只用于个人观察的小组情境，和对象字段 `targetGroupId` 分开。服务端核对本期组籍历史，有发生日期时还检查组籍与该北京时间自然日有交集。原文、登记时间和原有发生日期保留，旧记录未知的类型、课次和小组情境继续为空。

TeachingObservation 的原始行保留为第 0 版。归档前，具备本期有效教学身份的原作者可追加 `CORRECTED` 或 `WITHDRAWN`。本期有效教师还可撤回他人误记，包括作者已停用的记录。只有原作者能更正正文、情境或来源及发生日期。对象、类型、课次、小组情境及成果关联记错时，撤回后另记。撤回须填原因，默认列表不显示已撤回记录，可在课堂记录中显式纳入。记录 DTO 以 `canAmend` 和 `canWithdraw` 分别提供更正与撤回权限，写入事务独立鉴权。

`TeachingObservationRevision` 保存操作者、时间、修订号、原因和请求标识，数据库禁止改删修订行。服务在事务内检查预期修订号，同一成功请求原样重试返回原结果。读取时由最新修订决定有效内容和撤回状态，按需展开原文和历史。

TeachingFeedback 保留旧外发留言的对象、作者和可选的原成果上下文，TeachingFeedbackRecipient 保留发送时有效收件学生的快照。个人留言仅目标学生可读。组级留言由当时收件人与该组当前成员读取，新组员可接续阅读，离组者保留原来收到的留言。学生收件查询使用留言、收件快照和有权查看的成果，内部观察仍限教学团队阅读。关联成果后来不可读时只说明针对当时成果。留言及收件快照不可事后改删。当前界面保留已发留言的读取，停止独立新发。旧未发送的浏览器草稿仅可查看、复制或清除。底层兼容服务和已有数据继续保留。新的作业评语以 Review 写在对应成果版本。

新增模型的对象、收件人及同期开课的教学作者纳入成员角色历史保护。仅有内部观察的学生也受角色历史约束。归档后观察、修订与反馈供有权限者只读。内部观察的入口、读取及署名均以本期有效教师或助教身份授权，全站管理权限单独判断。

Post、Resource、GroupPage 显式保存发布状态和 visibility。PUBLIC 可公开展示；OFFERING 需服务端验证成员权限，枚举不自动提供行级权限。Post 可无开课，此时必须 PUBLIC。Resource 服务固定写入 OFFERING，仅教师或管理员管理；其他有效课程成员仅看 PUBLISHED，归档开课拒绝全部写入。

每条 Resource 可以附一个 ResourceFile，文件与资料状态在同一事务中保存。目录查询只取文件名和大小；打开资料时，服务按当前课程、成员身份与发布状态检查权限后才读取字节。只有旧说明、没有附件或网址的记录可按原文导出为 TXT。

AuthSession 仅保存随机 token 哈希、用户、有效期；原始随机 token 放 opaque cookie，并非签名 cookie。

CourseFocus 每期开课最多一份，保存教学团队自由编辑的当前标题与正文，不表示固定教学阶段或完整课表。CourseFocusAssignment、CourseFocusResource 按开课范围关联作业与资料，复合外键拒绝跨期引用。教师、助教或管理员可编辑，归档后只读；保存正文及关联在同一事务内替换。读取继续沿用原记录的可见性：学生可读已发布或已结束作业及已发布资料，不能通过关联读到草稿。助教编辑时保留其不可见的草稿/下架资料关联，避免修改正文时意外删除教师配置。

Prisma 7 的 datasource URL 由 prisma.config.ts 提供。初始迁移从空库 diff 生成，再加入 CHECK、partial unique indexes 和触发器，不能以 db push 替代。数据库规则不替代服务端授权。参与者学生身份、提交者是否有该提交归属的权限、封存时快照是否完整仍须服务端事务验证。

后续迁移 `20261018010000_history_guards` 固定 Review 的 offeringId、versionId、reviewerId，建立后不能更换来源或署名，仍允许修改评语和分数。成员角色历史保护同时涵盖个人提交归属、实际提交者、评阅者、成绩改分者、历史操作者、教学笔记作者，避免事后改角色改变历史含义；无上述记录的成员仍可正常变更角色。

2026-10-20 服务层落地：`teaching.ts` 在 Serializable 事务中独立鉴权，创建提交容器、递增版本、保存有效学生快照并封存，冲突时重试完整事务。请求 UUID 同时作为版本 ID；当前 requestFingerprint 核对正文、保留文件 ID、上传文件名和内容哈希，同一作者、同一作业及相同请求内容的重试返回原版本。无指纹的旧文字请求按原正文规则兼容。成功请求到期后重试不产生新记录；新的提交在服务端达到截止点时拒绝，除非符合指定已交成果的有效更正期限。归档课程拒绝新写入。

学生可读取固定个人归属的成果、自己在参与者快照中的历史版本，以及当前小组已有的共享正式成果。新组员读取不会回填旧参与者名单；离组者保留本人参与的原成果，不获得原组后续成果。当前进度以现在的个人或小组归属计算，教学团队按学生回顾参与经历时仍只列个人成果和实际参与版本，不把共享阅读当作贡献。成果详情、附件及关联反馈入口使用一致的读取规则；个人专属反馈与内部观察不会随组级材料扩散。教师/助教全期可读，只有有效教师/助教 CourseMember 可署名反馈，管理员权限不会伪造教学身份。当前 Review 仅写文字，score 保持空，不生成 GradeRecord。

作业发布后不可退回 DRAFT；从未发布的草稿不可直接 ARCHIVED，防止草稿通过“结束”状态泄漏。ARCHIVED 作业保留学生历史读取并停止新提交，仍可接受教学团队反馈；ARCHIVED 开课则全部只读。资料的 ARCHIVED 表示下架，对普通课程成员隐藏，两者含义分别在界面说明。

当前进度概览以有效个人/含有效学生的小组为应交对象，仅其最新封存版本参与当前统计。SubmissionVersionReview 独立记录待评阅、已完成及旧记录状态未知，SubmissionReviewEvent 保存状态变更；留言不自动完成评阅。更正生成新封存版本，旧版反馈及评阅记录保留原归属，不默认为新材料的反馈。空组和退出成员的版本仍在历史中。学生 progress 限定当前归属，教学 summary 与队列不返回给学生。

小组新提交要求客户端提供 expectedGroupId，并与事务内推导的真实组籍核对；该值不能选择或授予归属权限。若打开表单后调组，拒绝新写入。同一已成功 UUID 的幂等重试仍可返回原记录。浏览器草稿单独保存旧组上下文，改变正文或明确确认新组时生成新请求 UUID；原样重试继续沿用原 UUID，避免网络中断后重复提交或陷入正文冲突。

正式附件、更正期限和观察基础模型由迁移 `20261108000000_formal_deliverables_and_observations` 定义。迁移 `20261110000000_classroom_teaching_records` 追加课堂记录字段、复合外键、索引和修订表，沿用原观察的不可改写规则。迁移 `20261110001000_lesson_subject_observations` 仅替换对象的 `CHECK` 约束以允许整堂课记录，保留旧行原值。已有整课记录后，读取应用须识别两项对象字段均为空的情形。产生更正或撤回后，读取应用须应用修订，否则被更正的原文或已撤回的条目会重新出现在当前记录中。

现有 GroupPage 保存小组共享正文与保存修订。按发生时间、参与者和材料组织的轻量项目活动记录仍属后续批次，连同成果展示确认、助教动作权限细化及正式身份和名单对接，见[课程网站整体设计与分批实施](course-workflow-redesign.md)。

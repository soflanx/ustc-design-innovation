# 科大身份、课程名单与校历对接

正式使用时，师生身份、教师任课和学生选课关系将由校方教务接口提供，具体接口与授权方式待确认、接入。演示账号和手工维护课堂成员仅用于本地演示与测试。

## 目标体验

默认按教师本学期任教两门课、学生修读一门课设计入口。教师通过科大统一身份认证登录后，从自己任教的两门课中进入要备课的课堂。学生登录后直接进入自己修读的课堂。助教按校方名单进入相应课堂。数据库按每期开课保存成员关系，实际关联的课程数以教务名单为准。用户不用另外注册本站账号、填写邀请码或选择自己的教学角色。

思维课春秋均开；实践秋季Ⅰ、春季Ⅱ。课程类型规则由本站维护，具体学期、课堂及成员关系以学校提供的数据为准。

## 三个独立的数据来源

| 对接部分 | 负责的信息 | 本站对应边界 |
| --- | --- | --- |
| 统一身份认证 | 已验证的校方账号标识、必要的姓名等资料 | 绑定本地 User，建立本站会话 |
| 课程与名单 | 学期、课堂标识、任课教师、选课学生及助教关系 | 映射 CourseOffering 与 CourseMember |
| 校历 | 学期标识、正式上课日、结束日及调整 | 为自动开课提供日期 |

身份认证提供账号信息；每门课的学生、助教、教师权限仍由该课堂的名单确定。助教资格不能根据邮箱、院系或全校人员类型推断。对学校课堂的映射要使用校方提供的稳定标识，不靠课程名称模糊匹配。

同步名单时按本期课堂更新成员，不复制往期身份。退课或助教关系结束后停用相应成员关系，保留已有提交、参与快照与反馈。同步失败或名单不完整时，不把缺失记录当作退课，也不把某个学生自动提升为助教。

## 当前校历与后续替换

现有 `src/lib/ustc-calendar.ts` 已从教务处公开校历读取完整的春秋学期日期，并保留已核实快照供网络不可用时使用。这属于公开网页读取，尚未连接校内教务数据接口。

获得校方授权的数据源后，将校历读取替换为学校的数据适配器，保留来源、更新时间和完整性状态。发布界面继续自动带入日期；学校尚未公布完整日期或数据暂缺时显示“待同步”，不猜测结束日。校历可以与课程名单共用学校的学期标识，避免本站重复建立同一学期。

## 待校方确认后实施

科大[统一身份认证开发文档](https://id.ustc.edu.cn/doc/developer/)提供接入规范，新应用推荐 OAuth 2.0 授权码流程。网页应用需完成校内建站与接入申请；文档目前不支持校外应用对接，部署方式须一并确认。

课程名单、任课关系、助教关系及正式校历的数据接口、访问范围和同步方式尚未确认。已有[综合教务系统选课说明](https://www.teach.ustc.edu.cn/notice/notice-teaching/20425.html)及[助教系统通知](https://www.teach.ustc.edu.cn/notice/notice-teaching/19814.html)可用于联系业务部门，不据此假定这些系统已提供第三方 API。

接入前需确认校方账号标识与课堂标识、名单和校历的授权来源，以及数据更新和撤回的含义。本阶段只记录这些边界，不新增认证回调、同步任务或数据库模型。
